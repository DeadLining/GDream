# Chat 渲染整改验收 — 2026-09-25

## 根因

1. 原制作时间线仅在流式输出组件中渲染，idle 后退出渲染。因此结束后看不到，不全是没有保存。
2. 过程缓存另有历史运行数、步骤数、说明数、工具数与文本长度上限，超出部分确实丢失；确认历史仅在内存中。
3. 长输入直接展开，任务上下文和原始要求未分层。

## 实现

- AgentDrawer 将运行记录作为独立事件按时间插入；最终回复追加，不替换过程。
- RunStepTimeline 分开显示制作步骤、过程说明、阶段成果/分镜、确认记录和技术日志。工具回执、保存时项目快照是完成证据；模型计划不能作为完成凭据。生成提交成功不等同于媒体制作完成。
- CollapsibleInput 默认四行渐隐，自动任务摘要、附加上下文折叠，复制完整输入。折叠不改变发送内容与原始持久化内容；展开按钮保持滚动位置，关闭自动跟随到底部。
- 完整过程保存到用户目录下 `.gdream/chats/run-history/<sessionId>.json`，每会话串行临时文件写入/重命名，版本时间戳避免旧快照覆盖新记录。持久化错误在界面显式提示。
- 工具参数/回执脱敏；业务正文不再按旧上限截断。子任务完整结果同样保留。恢复时未完成状态标记中断，不恢复旧执行授权/确认 Promise，也不发起模型或生成调用。
- 以 ACP requestId 关联同名并发工具回执，拒绝执行有失败回执但不调用工具；未改变许可判断和生成请求路径。
