# Chat 代码质量整改 — 2026-09-25

## 范围

修复质量审查复现的三个缺陷：字符串工具回执漏脱敏、连续更新导致保存饥饿、删除会话未清理归档。保留已有未提交修改；不更新 DSH 上游、不调用真实模型或付费工具、不重启或改动已安装 GDream 的用户数据。

## 根因与修复

### 1. 统一技术证据脱敏

- 新增纯函数 `src/lib/chat/evidence.ts`，递归处理对象、数组、JSON 字符串和嵌套 JSON 字符串；混合日志/截断 JSON 使用敏感字段赋值、Basic/Bearer 和签名 URL 的文本过滤。
- 普通业务文字不截短。没有需要脱敏的 JSON 保留原格式。
- 工具摘要在截断之前脱敏。运行缓存、过程归档、最终消息工具回执和持久化 AgentMessage 工具结果/参数使用同一边界，避免完整结果被清理而摘要仍泄露。
- 加载旧过程归档也走相同清理；重写时保存清理后的记录。不会为此扫描、批量改写正在使用的用户数据目录。
- 用户原始输入另行保留，不因技术证据脱敏截断或修改实际发送内容。脱敏针对可识别的敏感字段/格式，不声称能识别任意无标签秘密文本。
- 过程归档改用已有 `write_text_file_private`，临时文件独立命名后重命名；临时文件在 finally 中清理。测试适配器验证最终文件权限 0600，未单独验收安装版 Rust 调用。

### 2. 有界保存与事件检查点

- 将不断重置的 trailing debounce 改成固定窗口调度：普通进度变化在 900ms 窗口内触发保存，不等流停止。
- 运行开始/状态切换、工具或子任务结束、确认请求/确认结果、阶段成果触发立即保存，即使另一个运行仍在进行。
- 仍采用单进程每会话串行写入和原子重命名。900ms 是调度界限，不保证磁盘阻塞时的 I/O 完成时间；突然断电前尚未落盘的窗口内内容仍可能丢失。

### 3. 删除是持久化状态，而不只是从数组移除

- 新增无业务内容的持久删除标记。删除请求立即阻止本进程的后续写入与历史恢复，再排队落盘删除标记并移除归档。
- 已删除的会话 ID 不复用。排队旧快照、之后到来的写入、新进程以及旧缓存都不能恢复已删除记录。
- 会话删除流程接入普通会话文件和执行归档删除；删除成功后才移除 UI 会话。普通会话的延迟写入也检查删除标记，避免只解决过程归档而留下会话文件。
- 删除/写入失败可观察且可以重试。独立临时文件减少多 WebView 临时文件冲突，但未增加跨进程完整事务锁，不声称支持同一会话的任意多进程并发编辑。
