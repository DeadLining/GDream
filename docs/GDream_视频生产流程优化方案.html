GDream 视频生产流程优化方案

目标：让整集视频在人物、道具、空间、机位、动作时间和声音上可追踪、可校验、可复现。

一、当前判断

项目已经具备分镜拆解、actionTimeline、资产引用、首尾帧继承、H3 提示词契约、生产审计和结构化连续性流程，但连续性主要依赖自然语言。下一阶段应把连续性从“提示词约束”升级为“结构化状态 + 生成前硬校验 + 冻结提交包”。

唯一数据模型跨镜头校验资产指纹已移除白模预演

二点一、单集与单镜头的拆解合同

每集先由剧本阶段确定事件和冲突，再由分镜阶段把事件拆成可拍摄的原子镜头。每个镜头必须有明确的开始状态、唯一目标动作、结束状态和时长；不能只生成一段长提示词。

镜头字段生成依据必须产出
镜头事实剧本事件、人物关系、场景shotNo、景别、机位、时长、镜头目标
状态账本上一镜 exitState 与本镜 entryState人物位置/朝向/姿态、道具持有/落点、环境声光
动作时间轴镜头时长、动作因果、对白节奏按时间段排列的动作事件，结束时间等于镜头时长
参考绑定首帧实际可见内容与资产库场景视角、实体人物、屏幕人物、资产道具
生成提示词以上结构化结果首帧 imagePrompt、视频 H3 prompt、声音描述
镜头 01-01：entryState → 0.00 秒首帧 → actionTimeline → exitState
镜头 01-02：继承 01-01 exitState，只写发生变化的动作
若发生换景、跨时或机位轴线重置，必须显式写 transitionPlan。

三、最高优先级改造

1. 拆分人物集合（已落地）

不要让 characterIds 同时表示实体人物、屏幕人物和所有可见人物。

physicalCharacterIds // 场景中实际出现
visibleCharacterIds   // 首帧中所有可见人物
screenCharacterIds    // 电视、手机、海报中的人物

首帧生图读取可见集合；实体人物参与空间连续性，屏幕人物拥有外观参考但不创建房间实体代理。

2. 拆分道具语义

assetPropIds       // 资产库中有外观图的道具
incidentalObjects  // 现场物件，无独立资产图

例如“夏至设计手稿”是资产道具，“散落花枝”是现场物件，不能互相替代。

四、结构化连续性账本

为每个镜头新增可比较的状态快照，而不是只保存长文本。

continuitySnapshot: {
  sceneId,
  cameraSignature,
  spatialAnchorSignature,
  lightingSignature,
  visibleCharacters: [{ id, presence, anchor, facing, posture }],
  props: [{ id, state, holder, anchor, contact }],
  framePath
}

下一镜声明 inherit 时，必须比较上一镜快照 → 本镜 entryState → actionTimeline → exitState；场景切换则明确使用 scene-cut。

五、已废弃：空间、白模与相机

该白模链路已移除，以下仅保留历史方案记录。

场景两张斜对角俯视图只负责建立唯一世界坐标和物体锚点，不是最终输出机位。建议给场景资产增加：

sceneSpatialProfile: {
  anchors: [{ id, label, side }],
  canonicalViews: ['diagonal-a', 'diagonal-b'],
  coordinateVersion: 1
}
  • 阶段 A：建立场景拓扑，不放人物、不加灯光、不加材质。
  • 阶段 B：依据本镜 0.00 秒状态放置实体人物、现场道具和相机，输出严格 9:16 纯白/中性灰白模。
  • 最终每镜只允许一个 stageBImagePath；重新生成直接覆盖旧图。
  • 写入前检查本机文件存在、PNG 指纹、尺寸和镜头 revision。

六、跨镜头一致性校验

新增 validateEpisodeContinuity(shots)，至少检查：

  • 上一镜尾状态与下一镜 entryState 是否一致。
  • 人物是否瞬移、消失或从屏幕人物变成实体人物。
  • 道具持有人、落点、完整/破损状态是否有可见交接过程。
  • 同场景相机侧别、画幅和主要光线是否突然变化。
  • 时间轴是否越界、倒置、重叠，最后结束时间是否等于镜头时长。
  • 转场是否只发生一次，且有 transitionPlan。
01-02：顾念上一镜站在电视前，本镜写成坐在床沿，但没有移动段或转场计划。
01-03：U盘上一镜在右手，本镜直接出现在桌面，缺少放下动作。
01-04：同场景相机从左前跳到右后，未声明 scene-cut 或受控转场。

七、Production Packet 冻结提交

付费生成前创建不可变提交包，实际任务只能读取它：

{
  shotNo, promptVersion, referenceSignature, referencePaths,
  actionTimeline, entryState, exitState, continuitySnapshot,
  imagePrompt, videoPrompt, generatedAt
  }

首帧生图和视频生成都必须创建 packet；其中 referencePaths 按最终绑定顺序冻结，referenceSignature 记录绑定版本，inputFingerprint 对提示词、参考图、音频和参数做指纹。任何剧本事实、资产、时间轴或提示词变化都使 packet 失效，必须重新生成，避免界面内容和实际提交内容不一致。

当前实现：视频与首帧生图均冻结 provider 输入

八、提示词生成规则收敛

  • 把重复规则抽成共享构建器：buildTimelineInstruction、buildReferenceInstruction、buildContinuityInstruction、已移除 buildWhiteboxInstruction。
  • actionTimeline 必须先写回并重新读取，之后才允许写视频提示词。
  • imagePrompt 必须引用真实最终资产顺序；空间信息由场景资产和结构化镜头状态共同约束。
  • H3 的 [ACTION_ENGINE] 逐段读取真实时间轴；不同 H3 模式遵循各自素材引用规则。
  • 首帧只描述 0.00 秒状态，不能提前加入后续动作或结尾状态。

九、实施顺序与验收

P0：先做数据正确性

人物集合拆分、道具集合拆分、连续性快照、生成前资产清单和硬校验。

P1：再做跨镜头可控性

episode continuity validator、相机/空间/灯光签名、production packet 和结构化空间字段。

P2：最后做维护性

提示词契约构建器、连续性状态表 UI、同场景拓扑缓存和更清晰的错误恢复。

验收标准

  • 每个镜头能明确列出实体人物、屏幕人物、资产道具和现场物件。
  • 任意相邻镜头可解释人物、道具、相机和空间状态如何从 A 变为 B。
  • 首帧、视频提示词、参考路径和签名来自同一个冻结 packet。
  • 历史白模字段和参考路径不会再次进入生成请求。
  • 时间轴、提示词、资产绑定和生成审计测试全部通过。

十、执行原则

剧本事实决定人物和动作；结构化状态决定连续性；场景资产和镜头状态决定空间与机位；资产图决定真实外观；时间轴决定动作持续时间；production packet 决定最终提交内容。

能力状态说明

生成前资产清单校验已接入检查场景、人物、道具和重复路径，失败时阻断提交。
跨镜头连续性门禁进行中已具备校验器，仍需接入所有 UI 生成入口。

十二、旁路入口收敛

画布和自动化工具存在直接调用生成核心的入口。它们必须复用工坊的参考绑定、连续性校验和 production packet，避免出现“工坊显示的资产”和“实际提交的资产”不一致。统一入口只接收冻结后的 packet，并把任务 ID、输入指纹和产物路径回写到同一镜头。

文档用途：后续可将本方案拆成独立 goal，按 P0 → P1 → P2 执行。内部存储路径和兼容键不应因品牌更新而改变。
