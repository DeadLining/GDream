# AI Comic Studio v0.4.0 Release Audit

Audited commit: `0926f71`

## Feature Gates

- Script sources: paste, TXT, DOCX, and text PDF extraction are covered by API tests. Scanned PDFs, malformed files, unsupported extensions, empty sources, and size limits have explicit failure tests.
- Import safety: parsing persists a review draft without mutating the project graph. Confirmation is transactional, merges characters, maps dialogue, preserves existing episodes, and rejects reconfirmation.
- Script creation: the workspace can generate a new draft from the existing project canon or automatically recognize imported material.
- Character references: decoded PNG/JPEG/WebP uploads and generated variants are immutable, reviewed, activated by type, and protected from invalid deletion.
- Reference-aware panels: characters present in a shot require approved active references; provider edits receive reference bytes and never silently fall back to text-only generation.
- Image-to-video: the runtime video channel drives MiniMax submission, polling, download, MP4 validation, immutable versions, activation, retry, pause, recovery, and bounded batch concurrency.
- Composition: active videos are preferred with static panel fallback. The deterministic fixture renders a verified 1080x1920 H.264/AAC MP4.
- Compatibility: Alembic migrations cover existing and fresh SQLite databases; previous projects and production-run records remain valid.

## Accepted Upstream Risk

`npm audit --omit=dev` reports GHSA-qx2v-qp2m-jg93 against `postcss@8.4.31`, an exact transitive dependency of the latest stable `next@16.2.10`. The npm-proposed automatic fix is a breaking downgrade to Next 9. The first patched Next package currently available is `16.3.0-canary.83`, which is not suitable for this release.

The advisory requires attacker-controlled CSS to be stringified and embedded in a style element. This local single-user application does not accept custom CSS, does not use `dangerouslySetInnerHTML`, and renders imported scripts and provider text through React text nodes and form controls. PostCSS is used only by the trusted Next build pipeline over repository-owned stylesheets. The vulnerable path is therefore not reachable from application input in v0.4.0.

Disposition: accepted as a non-blocking upstream build dependency risk. Upgrade to the first patched stable Next release and rerun `npm audit` when it becomes available.
